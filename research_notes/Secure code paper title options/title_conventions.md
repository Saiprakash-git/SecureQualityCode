# Title Conventions in LLM Secure Code Generation and LLM Code Security Evaluation (2023–2026)

Researched 2026-10-27. Every title below was checked against a primary or bibliographic source: an arXiv page, a publisher or university repository, or the reference list of a 2026 SoK whose PDF text I extracted. Venues come from those sources. Where sources disagree on a venue, the note says so.

Key bibliographic source: Patir, Guo, Cai, Hu, "SoK: AI Secure Code Generation: Progress, Pitfalls, and Paths Forward" (arXiv 2606.25195, 2026) — [arXiv PDF](https://arxiv.org/pdf/2606.25195). Its reference list (refs [1]–[57]) is cited as "SoK refs" below.

## Q1. Which title structures do accepted papers in this area use? (25+ verified titles)

### Takeaway
The dominant form is "Name: what it does" (system or benchmark name before the colon, a plain descriptive phrase after it). Second is the plain descriptive phrase with no colon, often a question ("Do users…?", "How secure is…?", "Can LLMs…?"). Empirical studies usually end the subtitle with a genre label: "An Empirical Study", "A Systematic Investigation", "A Targeted Replication Study". "Towards", "Rethinking", "Revisited" and "Paths Forward"/"Road Ahead" show up less often, mostly on SoKs, surveys and re-evaluations.

### Inferences
- In this subfield the "Name: subtitle" pattern is mostly used when the paper ships an artifact (tool or benchmark). The project's framework is only proposed, so a coined name before the colon would suggest a working system. A plain descriptive title or a "Main: Subtitle" without a coined name is the more honest choice.
- Measurement and replication papers rarely use coined names. They use plain nouns ("Security Weaknesses of…", "Assessing the Security of…") and a genre label ("An Empirical Study", "A Targeted Replication Study").
- Question titles appear in top-venue user and measurement studies (S&P 2022, CCS 2023, ICML 2025 BaxBench). They suit the measurement half but cannot also carry a proposal.
- In two cases the published title is shorter or sharper than the preprint title (Dai et al. at ICSE 2026; SVEN at CCS 2023). In one case the published title gained a genre label (Fu et al. at TOSEM). This suggests reviewers and editors steer titles toward clarity, though it is anecdotal evidence.

### Gaps
- I did not verify these titles on dblp itself. Verification came from arXiv, publisher and repository records, and the SoK's reference list.
- Several titles taken from the SoK reference list have only a year and no venue (CyberSecEval, SecRepoBench, the systematic literature review). Their venues are unconfirmed.
- I found no verified FSE or ASE main-track secure code generation titles within the tool-call budget.

## Q2. How are papers that combine an empirical study with a proposed approach or vision titled?

### Takeaway
The common pattern names both contributions in one subtitle, joined by "and" or a list: "A Comprehensive Evaluation, Framework, and Benchmarks"; "Progress, Pitfalls, and Paths Forward"; "Literature Review and the Road Ahead". The second element is a modest noun ("Road Ahead", "Paths Forward", "Framework") that signals direction without claiming results.

### Cited Findings
- "LLMs Cannot Reliably Identify and Reason About Security Vulnerabilities (Yet?): A Comprehensive Evaluation, Framework, and Benchmarks" puts the finding in the main title and lists the contributions in the subtitle — [IBM Research](https://research.ibm.com/publications/llms-cannot-reliably-identify-and-reason-about-security-vulnerabilities-yet-a-comprehensive-evaluation-framework-and-benchmarks)
- "Large Language Model for Vulnerability Detection and Repair: Literature Review and the Road Ahead" (TOSEM 2025) uses "X and the Road Ahead" for a review plus a forward-looking agenda — [SoK refs [54]](https://arxiv.org/pdf/2606.25195)
- "SoK: AI Secure Code Generation: Progress, Pitfalls, and Paths Forward" (2026) uses a three-part alliterative subtitle for assessment plus direction — [arXiv](https://arxiv.org/pdf/2606.25195)
- "Guiding AI to Fix Its Own Flaws: An Empirical Study on LLM-Driven Secure Code Generation": the main title states the goal, and the subtitle states that the paper is an empirical study — [arXiv](https://arxiv.org/html/2506.23034v1)
- "Assessing the Security of GitHub Copilot's Generated Code – A Targeted Replication Study" (SANER 2024) is a precedent for naming the replication outright in the title — [Polytechnique Montréal](https://publications.polymtl.ca/59071/)
- "WildCode Revisited: …" uses "Revisited" as a lighter alternative to "replication" — [arXiv](https://arxiv.org/pdf/2512.04259)
- "How Well Do Large Language Models Serve as End-to-End Secure Code Agents for Python?" puts an empirical question in the title, while the body also proposes a tool-assisted iterative repair approach that the title does not mention — [arXiv](https://arxiv.org/html/2408.10495v2)

### Inferences
- Templates that fit the project and avoid jargon (my inference from these patterns, not copied titles):
  - "[Finding or topic]: A Replication on Five Low-Cost Models and a Proposed Framework for …"
  - "[Topic] in Low-Cost LLMs: Replication Results and a Path Toward …"
  - "Are Cheaper LLMs Writing Safer Code? A Replication Study and a Proposal for …"
- The SoK and TOSEM examples show that "the Road Ahead" and "Paths Forward" are accepted at top venues for future-looking content. They read as agenda-setting, and reviewers do not take them as claims of a built system.

### Gaps
- I found no verified ICSE/FSE main-track title in this subfield with the exact form "An Empirical Study and a Framework for…". New Ideas / Vision track titles were not checked.

## Q3. What do authoritative sources say about title length, keywords, hype and colons?

### Takeaway
IEEE guidance says titles should be specific, concise and descriptive, should contain searchable keywords, and should avoid "new" or "novel". Bibliometric evidence links shorter titles with more citations, though the effect is modest and partly a journal effect. Colon titles are linked with fewer downloads and citations in one PLoS study, and question titles with more downloads but fewer citations. Hype words have risen sharply in abstracts, which supports avoiding them.

### Cited Findings
- IEEE Conference Author Center: "Your paper title should be specific, concise, and descriptive." "Avoid using unnecessary words such as 'new' or 'novel'." "Include keywords that will help a reader find your paper." — [IEEE Author Center](https://conferences.ieeeauthorcenter.ieee.org/write-your-paper/structure-your-paper/embed/)
- An IEEE author education video reportedly recommends 10–15 substantive words, and Editage recommends roughly 10–12 words. Both figures come from secondary summaries, and I did not view the IEEE video directly. — [GMU IEEE guide](https://infoguides.gmu.edu/ieee_style/write); [Editage](https://www.editage.com/insights/how-to-write-an-effective-title-and-abstract-and-choose-appropriate-keywords)
- Letchford, Moat, Preis (2015), "The advantage of short paper titles," Royal Society Open Science 2(8). The study covered 140,000 Scopus papers (2007–2013) and found that journals with shorter titles get more citations per paper. For 2011 papers, each extra character went with about 1.8% fewer citations. The lead author called the study a "proof of concept" that does not show causation and warned that titles should be "short as well as informative". — [Warwick WBS](https://www.wbs.ac.uk/news/size-matters-when-it-comes-to-academic-papers/); [Royal Society](https://royalsociety.org/news/2015/08/advantage-shorter-titles)
  - Conflict: the Royal Society news item says that for 2011–2013 there was no correlation between title length and citations, while the WBS release says the relationship stays significant after controlling for journal. — [Royal Society](https://royalsociety.org/news/2015/08/advantage-shorter-titles); [WBS](https://www.wbs.ac.uk/news/size-matters-when-it-comes-to-academic-papers/)
- Jamali & Nikzad (2011), "Article title type and its relation with the number of downloads and citations," Scientometrics 88(2):653–661. On 2,172 PLoS articles, question titles drew more downloads but fewer citations, colon titles tended to be longer and drew fewer downloads and citations, and longer titles were downloaded slightly less. — [IDEAS/RePEc](https://ideas.repec.org/a/spr/scient/v88y2011i2d10.1007_s11192-011-0412-z.html)
- Vinkers, Tijdink, Otte (2015), BMJ 351:h6467. Positive words in PubMed abstracts rose from 2.0% (1974–80) to 17.5% (2014), and "robust," "novel," "innovative" and "unprecedented" rose 2,500%–15,000%. The authors read this as hype and exaggeration. — [Retraction Watch summary](https://retractionwatch.com/2015/12/15/robust-novel-and-other-positive-terms-up-nearly-9-fold-in-abstracts-since-1974); [PDF](https://www.morrissey.unibe.ch/lecture/14_Vinkers_et_al_2015_pos_&_neg_Words_in_Abstracts.pdf)

### Inferences
- Aim for roughly 10–15 words, and put the main search terms ("LLM-generated code", "security", "secure code generation", "CWE") in the first half. Search snippets and the IEEE guidance both reward that.
- The colon evidence comes from PLoS biomedical journals. In CS security and SE venues, colon titles are standard (Q1 above), so the colon penalty probably does not carry over strongly. Still, keep each half short.
- Avoid "novel", "first", "comprehensive" and "unprecedented". Several field titles do use "Comprehensive", but IEEE guidance and the hype evidence both count against it.

### Gaps
- I found no bibliometric study specific to CS/SE security venues on title length, colons or citations.
- I did not find official ACM title guidance within the budget.

## Q4. Which words signal a proposal honestly, and how do reviewers perceive "Towards"?

### Takeaway
"Towards" is used at top venues (USENIX Security 2025 SoK, EMNLP 2024 SecCoder), but those papers deliver working artifacts or full systematizations, so in this field "Towards" does not mark unimplemented work. More reliable honest signals are genre nouns that cannot be read as results: "A Proposal", "A Vision", "A Design", "a Path Toward", "the Road Ahead", "Paths Forward". I found no empirical study of how reviewers perceive "Towards".

### Cited Findings
- "SecCoder: Towards Generalizable and Robust Secure Code Generation" (EMNLP 2024) is a fully implemented and evaluated system with "Towards" in the subtitle — [SoK refs [8]](https://arxiv.org/pdf/2606.25195); [arXiv](https://arxiv.org/html/2410.01488v1)
- "SoK: Towards Effective Automated Vulnerability Repair" (USENIX Security 2025) is a full systematization with "Towards" in the title — [SoK refs [55]](https://arxiv.org/pdf/2606.25195)
- "…and the Road Ahead" (TOSEM 2025) and "…Paths Forward" (2026 SoK) mark forward-looking agendas — [SoK refs [54]](https://arxiv.org/pdf/2606.25195); [arXiv](https://arxiv.org/pdf/2606.25195)
- "A … Framework for …" appears in titles of implemented systems: "SCodeGen: A Real-Time Trustworthy Constrained Decoding Framework…" and "AutoSafeCoder: A Multi-Agent Framework…". So "A Framework for X" alone reads as a built system. — [SoK refs [10],[16]](https://arxiv.org/pdf/2606.25195)
- A search for reviewer-perception studies of "Towards" titles returned nothing relevant — [search, no source]

### Inferences
- Because "A Framework for…" usually means an implemented framework in this field, an unimplemented framework should carry a qualifier such as "A Proposed Framework", "A Design for", "A Proposal for" or "a Path Toward". "Towards" on its own is ambiguous: it is common on implemented systems.
- "Plan" or "Blueprint" are plain-language options too, but I did not verify any example in this subfield.
- Suggested honest pairings, as inferences: "… and a Proposed Framework for …"; "… and a Path Toward Requirement-Driven Secure Code Generation"; "… with a Proposal for …".

### Gaps
- I found no empirical or survey evidence on reviewer perception of "Towards" (for example, whether it signals incremental work). Any claim about that is anecdotal.
- I found no verified title in this subfield that uses "Proposal" or "Vision" explicitly, so that pattern needs checking (for example in ICSE NIER or FSE IVR track listings).
